Open Authorization (OAuth):
    OAuth is an authorization framework that allows an application to access a user's 
    resources on another service without the user giving the application their password.

    Example: 
        - Sign in with Google
        - The application doesn't need your Google password. Instead Google authenticates you and gives the 
           application an access token that grants limited access. 

OAuth vs JWT:

    OAuth: 
        - Authorization framework
        - Defines how authorization happens
        - Defines flows & roles 
        - can use different token formats 

    JWT:
        - Token format 
        - Defines how information is represented in a token 
        - Contains Claims
        - Can be used as access tokens
            

OAuth Participants:

    - Resource owner        : User
    - Client Appliation     : Frontend Appliation
    - Authorization Server  : Google / Microsoft / Okta
    - Resource Server       : Backend Application 


OAuth Workflow: 

    1. User clicks "Login with Microsoft"
                    │
                    ▼
    2. React redirects user to Microsoft
                    │
                    ▼
    3. Microsoft authenticates user
                    │
                    ▼
    4. User grants permission
                    │
                    ▼
    5. Microsoft redirects back with Authorization Code
                    │
                    ▼
    6. Client exchanges Code for Tokens
                    │
                    ▼
    7. Authorization Server returns Access Token
                    │
                    ▼
    8. Client calls API using Access Token


OAuth URL format: 

    https://auth.example.com/authorize?
        client_id=12345
        &redirect_uri=https://myapp.com/callback
        &response_type=code
        &scope=profile

    - client_id       : identifies your application
    - redirect_uri    : Where the user should be redirected afterwards
    - response_type   : request an authorization code
    - scope           : permisions beign requested 


    1. Google OAuth 2.0 

        https://accounts.google.com/o/oauth2/v2/auth
            ?client_id=YOUR_CLIENT_ID

PKCE (Proof Key for Code Exchange):

    - OAuth uses PKCE mechanism for authorization Workflow
    - PKCE is an important security mechanism is used in Authorization code flow.
    - It consist of two main components: 
        - code_verifier  : a random secret string generated by the client 
        - code_challenge : Base64Url encoded SHA256 of code_verifier

PKCE Flow: 

    1. Generate Code Verifier 
        - const codeVerifier = generateRandomString();

    2. Generate the Code Challenge 
        - code_challenge = Base64UrlEncode(SHA256(code_verifier))

    3. Redirect to AUthorization server with code challenge

        - GET https://auth.example.com/authorize?
                client_id=my-react-app
                &response_type=code
                &redirect_uri=https://myapp.com/callback
                &scope=openid profile
                &code_challenge=abcXYZ123
                &code_challenge_method=S256

    4. User Authenticates using username & password (Ex. Google login)

    5. Authorization returns code to the client application

    6. Client App sends both token & code verifier to Authorization Server 

        POST https://auth.example.com/oauth2/token

            Content-Type: application/x-www-form-urlencoded

            Request Body: 
                grant_type=authorization_code
                &client_id=my-react-app
                &code=AUTH_CODE_123
                &redirect_uri=https://myapp.com/callback
                &code_verifier=random-secret-xyz

    7. Authorization server verifies PKCE  

        - now authorization server has both code_challange & code_verifier now it encryptes the code_verifier using SHA256.
        - And encodes it in Base64URL format if it matches the code challenge.
        - It retruns the bearer token to the client application
        - If the code challenge does not match it rejects the request.
